# Dual POC implementation plan
Goal: preserve gap review and add a separate verified dataset retrieval program under one launcher.
Approved scope: start building, dataset-only product facts; responsible general reasoning may interpret and connect evidence, labelled as inference.
Architecture: existing Gap Console and new Retrieval Console share Infrastructure/Core and Python ingestion/search. A Launcher selects one executable without a nested Codex console. Codex remains reasoning; Ollama qwen3-embedding:4b remains embeddings.

1. Add tests for normalization token preservation, exact citation provenance, complete verifier claim checking, failed-closed output, evidence snapshot and history isolation; run red before implementation.
2. Add knowledge_qa schema migration: sessions, turns, events and evidence links to immutable source versions/content units or saved review records. History is not embedded/promoted. Original question and normalized form always retained. Commit run status/failure incrementally.
3. Add KnowledgeRetrieval orchestration: normalize, HNSW retrieve, draft, deterministic citation validation, semantic verifier, at most one correction. Only publish supported verified claims; distinguish reasoning from facts, source content from unapproved historical reviews, and transcription from visual evidence. Persist every stage.
4. Add Launcher and Retrieval console projects; preserve gap commands and worker compatibility. Add direct start/export commands; extend setup to apply additive migration. No rebuild while a child host is running.
5. Add contracts, editable instructions, docs and demo tests. Run Python suite, .NET build and host orchestration checks with controlled Codex fixtures. DB integration if disposable PostgreSQL is available. Never claim live Windows/Codex/Ollama validation from fixtures.

Review focus: typos changing version/identifiers; invented citations; unsupported premise; prompt injection in evidence; failed verifier or database save; timeout/cancel; mode leakage; follow-up stale context; duplicate answer ingestion. No raw query interpolation. Reviewer will check whole changes after implementation.
Progress: baseline 0.17 recovered, no user database touched.
