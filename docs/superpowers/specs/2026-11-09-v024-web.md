# v0.24 local web workspace
Approved user goal: CMD setup/start, choose POC1 or2, readiness + Qwen warmup + scan, local URL, real agent windows. Per-chat retained history and context in BOTH POCs, survives restart. Attach/paste images remain chat-only (approved A); not embedded or added to global knowledge. Link every cited local source + original website if available; show relevant cited article images and video frames, with provenance. POC1 /review ->A->B->saved embedded findings ->C; /results, /ask, /search retained and isolated per chat.

Architecture: add ASP.NET Core .NET10 Web project using same runtime/Core/Python worker and existing Codex login, no new API key or Node prerequisite. Clean static HTML/CSS/JS frontend served by that host. Launcher chooses mode then runs Web host with --poc1/2; original console projects remain fallback. Bind loopback only. One global active job per server (existing Runtime role window state is single-owner); user can switch/view/create chats while busy but cannot overlap model/process jobs. Progress polling + Stop button cancels role via existing cancellation mechanism. Scan automatic, processing manual.

Persistence: additive workspace_ui schema, chats(poc,title,context JSON,timestamps), messages(role,text,payload), assets(owner chat, kind,path,digest,source metadata). Context rehydrated from approved intent snapshot, not AI source facts. POC2 uses stable per-chat session id, restores intent; POC1 stores exact selected run and recent user conversation; refreshes report before asking. Full history retained; bounded recent intent used for reasoning. Uploaded PNG/JPEG/WebP max10MB, max4 per turn; MIME/signature/dimension checks, normalize image pixels with Pillow. Store files outside versioned solution in configurable WebDataRoot (default user LocalAppData/Contoso/Workspace). Persist references/hashes, never image blobs/vectors. No automatic import of old CLI chats; existing saved gap runs selectable via /results. Existing old CLI QA audit records remain in database.

Images: uploads passed to normalizer/knowledge/verifier as untrusted problem context, user-image evidence distinguished from original product docs. Shared across follow-ups within chat with bounded selection; user can deselect. Add original article markdown-linked screenshots only from cited/retrieved original paths, never arbitrary remote fetch. Candidate images selected by source link and provided to both answer+verifier before claims; no fabricated screenshots. Output gallery restricted to final cited evidence and relevant source images selected by agent with independent visual checks. Uploaded image observations can describe visible content, but do not establish general product behaviour. Final hash/freshness guards retained. POC1 chat attachments are contextual only; do not mutate saved A/B review.

Security: no arbitrary file endpoint, no directory listing; opaque per-chat assets, canonical containment and no symlink escape; bounded uploads; no executable source HTML/SVG served inline. Text/article preview escaped, links HTTP(S) only, reject javascript URLs and raw HTML. CSRF same-origin guarded JSON/token, loopback Host validation. No exposed credentials/raw internal prompts. Single active work serialization per server plus DB expiring lease across instances. No fake live answers; test-mode backend only explicit and visibly labelled for UI QA.

Design: readable business chat, white/coolgray surfaces, dark teal accent. Left chat sidebar/New chat, mode header, central transcript, source links/image gallery, attach/paste composer, agent status and Stop. Source modal provides title/path/locator + escaped text or media preview/download; original URL separate. Lightbox for images. Mobile sidebar toggle and keyboard focus/labels. No decorative assets, marketing, or fabricated product screenshot assets in shipped app.

Non-goals: LAN deployment/accounts, global learning from uploads, unsupported sources, new embedding model, automatic processing, full media inspection. Persistent history doesn't turn previous AI answers into evidence. Framework choice and file-root default are engineering choices documented for operator.
